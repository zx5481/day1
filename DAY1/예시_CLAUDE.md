# CLAUDE.md — 돌담귤방 (예시)

> 1일차 2교시 예시입니다. 오늘은 개인 연습 저장소(boost-practice)에서 돌담귤방을 그대로 쓰거나, 내가 지은 가상 가게로 바꿔 쓰세요. 규칙은 한 줄씩, 확인할 수 있는 말로.
> 2일차부터는 이 틀로 개인 프로젝트의 규칙을 쓰고, DAY 6 에는 팀 규약으로 넓힙니다.

## 1. 프로젝트 한 줄
가상의 서귀포 감귤 농가 「돌담귤방」의 상품 안내 사이트. 손님 한 명: 설 연휴 전, 부모님께 보낼 3~5만 원대 선물을 찾는 서울 직장인.
(강사 시연용 가상 가게. 수업에서는 이 사이트 위에 상품 · 선물 추천 에이전트를 시연한다.)

## 2. 기술
- HTML · CSS · 순수 JavaScript. 빌드 도구 · 프레임워크 없음.
- 계산 함수는 app.js 에 화면 코드와 분리 — node 에서도 require 로 테스트할 수 있게.
- 4일차부터 Vercel 서버 함수(api/ 폴더)를 쓴다.

## 3. 폴더 구조
```
index.html     첫 화면 (상품 목록)
style.css      스타일
app.js         계산 함수 + 화면 연결
products.json  상품 데이터 (가상의 예시 값)
test/          node --test 테스트
spec.md        명세  ·  작업로그.md  작업 기록
```

## 4. 코드 규칙
- 함수는 한 가지 일, 30줄 이하.
- 이름은 영어(camelCase), 화면 글자는 한국어.
- 데이터를 화면에 넣을 때는 textContent — innerHTML 에 데이터를 그대로 넣지 않는다.
- 새 기능은 spec.md 에 먼저 적고 시작한다.

## 5. 금지
- API 키 · 비밀번호를 코드 · 커밋에 쓰지 않는다 (4일차부터 Vercel 환경변수에만).
- 실제 개인정보(이름 · 전화번호 · 주소), 실제 가게의 상표 · 로고 · 사진을 쓰지 않는다.
- 테스트 파일을 고쳐서 테스트를 통과시키지 않는다.

## 6. 확인 방법
- 커밋 전에 `node --test` 모두 통과.
- Browser 패널에서 휴대폰 크기(390px)로 가로 스크롤 없음 · 키보드 Tab 으로 모든 버튼에 갈 수 있음.

## 7. 커밋 규칙
- 한 커밋 = 한 가지 변경.
- 메시지: `종류: 무엇을` — feat(기능) · fix(버그) · test(테스트) · docs(문서) · style(모양)
- main 에는 테스트를 통과한 것만. 새 작업은 feature/이름 브랜치에서. (DAY 6 팀 저장소에서는 member/별명 브랜치)

## 8. 오늘 배운 규칙 (7교시에 추가)

- (예) 리뷰 의견은 반영 · 안 함 · 나중에 를 사람이 정한다.
